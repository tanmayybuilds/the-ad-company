# Section 06: campaign pathway team tour

`src/components/site/TeamTour.tsx` replaces the former team grid through the existing `Sections.tsx` export. The `#team` navigation and coverage skip link continue to work. All six supplied profiles, colors and world positions live in `src/content/site.ts`. Names and stock portraits are explicitly labelled as illustrative pending roster confirmation. Portrait sources are in `team-portraits.md`.

The 550vh wrapper uses a native sticky 100vh viewport. One demand-driven requestAnimationFrame loop updates the world transform, path fills and distance opacity directly. Target progress is always a whole pointer index; React updates on stage changes. Cubic Hermite interpolation reaches every supplied coordinate exactly. Damping is normalized to elapsed time (equivalent to .085 at 60Hz), with a 900ms completion bound that settles the camera at its exact destination. Motion stops while settled, outside the section, in a hidden tab, or with reduced motion enabled. There are no continuous idle effects or pointer-driven animation loops.

The close-up camera uses 1150px perspective with a centered 50% 50% origin, a 14-degree downward viewing angle and 80px camera depth. CSS screen Y points downward, so the pitch is expressed negatively, with matching positive billboard correction. The shared `--tour-pitch` keeps portraits and cards facing the lens as the camera is raised. Camera banking and mouse parallax remain disabled.

`teamFraming` adapts the world scale to viewport width and height while enlarging the active portrait and card independently. At common desktop sizes, the calculated resting projection produces a pedestal at least 175px wide, a portrait at least 250px tall, and introduction text above 15px. Role cards sit closer to the portrait at a 155px offset, with width fitting for both card sides. The camera follows the same six world coordinates at the closer distance throughout the journey. Compact layouts below 1024px use the enlarged portrait above a centered profile panel instead of squeezing a beside-card against the viewport edge. Pointer numbers face the lens across the front lip.

Rendering is limited to three consecutive stops and their two connecting paths. Hidden assemblies use `display: none`, and promotion with `will-change` lasts only while the camera is moving. The floor is a stationary viewport-sized decoration instead of a 6500 x 7000px transformed surface. Portrait filter chains and blurred pedestal shadows are removed. Local portraits use 380 x 520 WebP derivatives instead of 600px-wide JPEGs.

The Services image sequence also loads only a nine-frame window around the current frame (one frame with reduced motion). It prioritizes the target, retains nearby frames for reverse scrolling, and releases image references and canvas backing storage outside its viewport margin or when the tab is hidden. For 1080 x 608 RGBA pixels, the frame-reference budget changes from approximately 666 MiB (266 frames) to 22.5 MiB (nine frames), excluding browser caches and the display canvas. These are calculated pixel budgets, not measured browser process memory.

While the tour is pinned, each downward wheel gesture advances one pointer. Trackpad momentum stays grouped until 180ms of input silence; a long flick cannot re-arm itself after an arbitrary timer. Input during camera travel is consumed rather than queued. A fresh downward gesture after pointer 06 exits normally. Downward touch swipes and ArrowDown/PageDown/Space use the same integer destinations; repeated keydown events do not skip stages. Horizontal gestures, pinch zoom, editable controls, locked dialogs, reduced motion and scrolling outside the tour retain their native behavior.

Upward wheel, touch and keyboard input immediately cancels camera travel, resets pointer 01 and crosses the pinned start boundary using the same `exitReversePin` helper as Services and Coverage. Native upward scrolling, including re-entry from the contact section, takes this exit too. A later downward visit begins at pointer 01. Explicit profile pills and previous/next buttons still let the visitor choose any stop, including backward navigation. Direct `#team` links reset and open the tour rather than being mistaken for reverse scrolling.

Navigation moves the document to the exact stop offset immediately while only the 3D world animates. Its internal scroll position is recorded before the programmatic move, so that scroll event cannot accidentally trigger another step or the upward exit. Bounds refresh after resize, section resize and GSAP ScrollTrigger refresh. A contact link provides a direct way out of the tour. All controls are native keyboard-operable buttons; hidden nodes are inert. Reduced-motion visitors receive all six profiles in a normal document layout without a long pinned scroll. Narrow screens use a readable active profile panel below the 3D scene.

Validation: `npm test` includes long wheel inertia, one-stop gestures, input during travel, upward interruption and re-entry, last-stop exit, projected close-up sizes at common desktop resolutions, compact portrait size limits, camera-stop mapping, interpolation continuity, overshoot checks, floor path endpoint geometry, the three-stop render window and bounded service-frame selection in both directions. The shared reverse-exit tests cover exact boundaries and locked dialogs. `npm run build` checks TypeScript and the production bundle. Visual browser inspection is not run automatically per this repository's AGENTS.md. A locked 60–120fps rate is hardware-dependent and has not been measured. No publication is performed without an explicit request, per the repository README.
